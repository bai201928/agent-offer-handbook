# 第 1 章：先看懂一段 Java 程序怎样真正跑起来

## 本章目标

建立源码、字节码、JVM、对象、参数和值之间的完整画面。学完后，后续集合、并发和 JVM 章节不再是孤立名词。

## 前置知识

不要求任何 JVM 基础，只需要会写简单 Java 类。

## 本章学习路径

```text
Java 源码 → javac → 字节码 → 类加载 → 解释/JIT → 栈与堆 → 方法返回
```

> 本章不是按旧八股文件的出现顺序排列，而是按“先能运行，再解释原理，最后处理故障”的认知顺序组织。

### Q001：一段 Java 代码从源码到执行经历了什么？

**题型**：核心面试题｜初学者必会　｜　**频率**：★★★★★

**为什么现在学**：这是整套教材的起点。不了解程序如何运行，后面谈 JVM、对象、线程和 Spring 都会变成背术语。

#### 1. 先用人话理解

把 Java 程序想成一份跨国使用的说明书。`.java` 是人写的原稿，`javac` 把它翻译成统一的 `.class` 字节码；不同操作系统上的 JVM 再把字节码解释或编译成当地 CPU 能执行的机器指令。JVM 同时负责类加载、内存分配、线程调度接口和垃圾回收。

#### 2. 它在 JVM / 框架里怎么运行

1. 源码由 `javac` 编译为 Class 文件，里面包含字节码、常量池和类结构信息
2. 类加载器找到 Class，JVM 完成加载、验证、准备、解析和初始化
3. 方法首次执行通常可由解释器快速启动；热点方法达到阈值后由 JIT 编译成本地机器码
4. 执行过程中线程在自己的栈中建立栈帧，对象通常分配到共享堆中
5. 对象不可达后由垃圾收集器在合适时机回收

#### 3. 贯穿项目怎么用

Agent 请求进入 Controller 后，DTO 类要先被加载；Service 方法调用会创建栈帧；会话、检索结果和模型响应对象进入堆；高频序列化和路由代码可能被 JIT 优化。

#### 4. 可读但容易出事故的写法

```java
// 错误认知：以为 class 文件可以直接被 CPU 执行
Runtime.getRuntime().exec("TaskService.class");
```

#### 5. 更稳妥的企业级写法

```java
// 正确做法：由 JVM 加载并执行字节码
public static void main(String[] args) {
new TaskService().run();
}
```

#### 6. 2～3 分钟面试口述

> Java 的执行链可以概括为两次转换：源代码先由 javac 编译成平台无关的字节码，运行时再由 JVM 把字节码解释或 JIT 编译为当前平台的机器码。JVM 不只是翻译器，它还负责类加载、运行时内存、线程和垃圾回收。程序启动时解释执行可以缩短启动时间，热点代码随后被 JIT 编译并缓存，从而获得接近本地代码的执行效率。因此跨平台的是字节码，不是 JVM 本身；Windows、Linux 和 macOS 需要各自的平台 JVM。项目排障时我也会沿这条链看问题：是编译、类加载、JIT、内存还是业务代码导致的。

#### 7. 面试官递进追问

- 为什么 Java 既可以说是编译型语言，也可以说是解释型语言？
- JIT 编译后的机器码存在哪里？

**记忆钩子**：源码给 javac，字节码给 JVM，热点代码给 JIT。

### Q002：JDK、JRE、JVM、字节码分别是什么关系？

**题型**：高频基础题　｜　**频率**：★★★★★

**为什么现在学**：这些词经常一起出现。只背“JDK 包含 JRE”容易在现代 JDK 中答得过时。

#### 1. 先用人话理解

JVM 是执行字节码的虚拟机；Java 类库加 JVM 构成运行所需能力；JDK 再提供编译器、诊断工具、打包工具等开发能力。过去常把运行环境单独称为 JRE，但现代 JDK 发行版通常不再单独提供传统 JRE 安装包，生产环境可用 `jlink` 生成裁剪运行时。

#### 2. 它在 JVM / 框架里怎么运行

1. JVM 执行 Class 字节码并管理运行时资源
2. 标准类库提供 `java.lang`、集合、并发、I/O 等 API
3. JDK 包含 `javac`、`java`、`jcmd`、`jstack`、`jmap`、`jfr` 等开发与诊断工具
4. `jlink` 可根据模块依赖构建更小的自定义运行时镜像

#### 3. 贯穿项目怎么用

项目开发机安装完整 JDK；容器镜像可以使用精简 JRE 类镜像或 jlink 产物；线上故障容器至少要有可用的诊断工具或 Sidecar 方案。

#### 4. 可读但容易出事故的写法

```java
// 只复制 class 文件，却没有 Java 运行时
COPY target/classes /app
CMD ["/app/Main.class"]
```

#### 5. 更稳妥的企业级写法

```java
// 使用 JDK 构建、运行时镜像启动
CMD ["java", "-jar", "/app/agent-platform.jar"]
```

#### 6. 2～3 分钟面试口述

> JVM 是执行 Java 字节码的核心运行引擎；JDK 是开发工具包，除了 JVM 和标准类库，还包括 javac、jar、jcmd、JFR 等编译与诊断工具。传统教材中的 JRE 可以理解为 JVM 加运行所需类库，但现代 Java 发行方式已经不强调单独安装 JRE，常见做法是使用 JDK 运行，或者通过容器基础镜像、jlink 生成裁剪运行时。字节码则是 Java 源码编译后的平台无关中间形式。面试时我会强调：跨平台的是 Class 字节码，同一个字节码需要由不同平台版本的 JVM 执行。

#### 7. 面试官递进追问

- 为什么生产镜像不能为了小而完全删除诊断能力？
- `jlink` 的价值是什么？

**记忆钩子**：JVM 负责跑，类库负责用，JDK 负责开发和诊断。

### Q003：为什么说 Java 参数传递只有值传递？

**题型**：高频基础题　｜　**频率**：★★★★★

**为什么现在学**：对象参数最容易被误称为“引用传递”，会直接影响你理解集合修改、并发共享和方法边界。

#### 1. 先用人话理解

调用方法时，Java 总会复制一份参数值。基本类型复制数字本身；对象变量中保存的是“指向对象的引用值”，调用时复制的是这份引用值。两个引用都能访问同一个对象，所以修改对象内部字段能被外部看到；但把方法内的参数重新指向新对象，不会改变调用方变量。

#### 2. 它在 JVM / 框架里怎么运行

1. 调用点计算实参值
2. JVM 把值复制到被调用方法栈帧的局部变量表
3. 基本类型副本与原变量独立
4. 引用类型复制的是引用值，两个引用暂时指向同一堆对象
5. 方法内重新赋值只改变参数副本

#### 3. 贯穿项目怎么用

Agent 方法收到 `AgentContext` 后可以修改其中的步骤列表；但 `context = new AgentContext()` 不会替换 Controller 中原来的引用。因此共享可变对象要谨慎。

#### 4. 可读但容易出事故的写法

```java
void reset(AgentContext c) {
c = new AgentContext(); // 调用方引用不会改变
}
```

#### 5. 更稳妥的企业级写法

```java
AgentContext reset(AgentContext old) {
return new AgentContext(); // 显式返回新对象
}
```

#### 6. 2～3 分钟面试口述

> Java 的参数传递只有值传递。基本类型传递的是数值副本；对象参数传递的是引用值的副本，而不是把调用方变量本身交给方法。因为原引用和副本一开始指向同一个堆对象，所以方法通过副本修改对象字段，调用方能看到变化；但方法把参数重新赋值为新对象，只改变自己的局部变量，调用方引用不会改变。这个区别在项目中很重要：传入可变上下文并修改它会产生共享副作用，而返回一个新对象更容易控制状态和并发安全。

#### 7. 面试官递进追问

- 为什么 `swap(a,b)` 不能交换调用方的两个对象变量？
- 不可变对象为什么更适合跨方法和跨线程传递？

**记忆钩子**：能改共同对象，不能改对方变量的指向。

### Q004：基本类型、包装类型、自动装箱和 Integer 缓存怎么理解？

**题型**：高频基础题　｜　**频率**：★★★★☆

**为什么现在学**：它决定集合为什么只能放对象、空值为什么会拆箱 NPE，以及 `Integer ==` 为什么结果不稳定。

#### 1. 先用人话理解

八种基本类型保存直接值，包装类型是对象。泛型和集合只能接收引用类型，所以 `List<Integer>` 会自动把 `int` 装箱成 `Integer`。拆箱时如果包装对象是 `null`，会抛空指针。部分小整数对象会被缓存，因此 `==` 有时为真，但对象内容比较始终应使用 `equals`。

#### 2. 它在 JVM / 框架里怎么运行

1. 编译器把 `Integer x = 1` 改写为 `Integer.valueOf(1)`
2. `int y = x` 改写为 `x.intValue()`
3. `Integer.valueOf` 对常见小整数区间复用缓存对象
4. `==` 对对象比较引用是否相同，`equals` 比较数值内容

#### 3. 贯穿项目怎么用

租户配额、超时和重试次数从配置中心读取时常为包装类型；必须区分“未配置 null”和“配置为 0”，并避免自动拆箱 NPE。

#### 4. 可读但容易出事故的写法

```java
Integer timeout = config.getTimeout();
if (timeout > 0) { } // timeout 为 null 时 NPE
```

#### 5. 更稳妥的企业级写法

```java
int timeout = Optional.ofNullable(config.getTimeout())
    .orElse(3000);
```

#### 6. 2～3 分钟面试口述

> 基本类型保存直接值，包装类型是对象，用于泛型、集合以及表达 null。自动装箱和拆箱只是编译器帮我们插入 `valueOf` 和 `xxxValue` 调用，并不是没有成本。面试常见坑有两个：第一，包装对象可能为 null，自动拆箱会抛 NPE；第二，Integer 对小整数有缓存，所以 `==` 在某些值上看似成立，但它比较的是对象引用，业务比较应使用 `equals` 或先拆箱。工程上我会在配置和 DTO 边界明确 null 语义，进入核心计算后尽量转成确定的基本类型。

#### 7. 面试官递进追问

- 为什么泛型不能直接写 `List<int>`？
- 频繁装箱会带来什么性能影响？

**记忆钩子**：集合放对象，拆箱防 null，包装比较用 equals。

### Q005：为什么金额、评分或精确计费不能直接用 double？

**题型**：场景面试题　｜　**频率**：★★★★☆

**为什么现在学**：浮点精度问题在支付、Token 计费和模型成本统计中都可能造成真实数据偏差。

#### 1. 先用人话理解

`double` 使用二进制浮点表示，很多十进制小数无法被有限位二进制精确表示，例如 0.1。`BigDecimal` 用十进制数值和标度表达精确小数，但构造、除法、舍入和比较方式也要正确。

#### 2. 它在 JVM / 框架里怎么运行

1. 浮点数按 IEEE 754 二进制格式保存近似值
2. `new BigDecimal(double)` 会把近似误差一起带入
3. 优先用字符串构造或 `BigDecimal.valueOf`
4. 除法可能无限循环，必须指定精度和舍入模式
5. `compareTo` 适合数值比较，`equals` 还比较标度

#### 3. 贯穿项目怎么用

Agent 平台统计人民币成本、美元模型账单或 Token 单价时，应在数据库和 Java 中统一精度、标度与舍入规则。

#### 4. 可读但容易出事故的写法

```java
BigDecimal price = new BigDecimal(0.1);
boolean same = price.equals(new BigDecimal("0.10"));
```

#### 5. 更稳妥的企业级写法

```java
BigDecimal price = new BigDecimal("0.10");
BigDecimal total = price.multiply(BigDecimal.valueOf(3));
boolean same = total.compareTo(new BigDecimal("0.30")) == 0;
```

#### 6. 2～3 分钟面试口述

> `double` 适合科学计算和允许误差的指标，不适合要求十进制精确的金额与计费，因为 0.1 等十进制小数在二进制浮点中只能近似表示。精确场景应使用 BigDecimal，并且从字符串或 `valueOf` 创建，避免把已有浮点误差带进去；做除法要明确 scale 和 RoundingMode；比较数值通常用 `compareTo`，因为 `equals` 还会比较小数位数。企业项目还要让数据库 DECIMAL、Java BigDecimal、接口字段和对账规则使用同一套精度与舍入策略。

#### 7. 面试官递进追问

- 为什么 BigDecimal 仍然不是“自动正确”？
- 数据库字段该怎样与 BigDecimal 配合？

**记忆钩子**：浮点求快，BigDecimal 求准，准还要统一舍入。

### Q006：String 为什么不可变？字符串常量池和 new String 有什么区别？

**题型**：核心面试题　｜　**频率**：★★★★★

**为什么现在学**：String 是日志、缓存键、Map Key、类名和协议字段的基础，不可变性也是很多安全和性能设计的前提。

#### 1. 先用人话理解

String 创建后字符内容不能修改。所谓拼接产生新 String。不可变带来哈希值稳定、可安全共享、适合常量池和 Map Key，也降低并发保护成本。字符串字面量可进入字符串池复用；`new String("abc")` 通常额外创建堆对象。

#### 2. 它在 JVM / 框架里怎么运行

1. 字面量由 Class 常量池记录，运行时可引用字符串池中的对象
2. String 内部状态不向外暴露可修改入口
3. 拼接在编译期可能折叠，运行期循环拼接通常用 StringBuilder 更合适
4. `intern()` 返回池中规范化引用，但不应滥用

#### 3. 贯穿项目怎么用

租户 ID、模型名、Trace ID 常作为 Map Key；如果 Key 可变，放入哈希表后再修改会导致无法找到。日志循环拼接则应避免制造大量临时 String。

#### 4. 可读但容易出事故的写法

```java
String result = "";
for (String token : tokens) result += token;
```

#### 5. 更稳妥的企业级写法

```java
StringBuilder result = new StringBuilder();
for (String token : tokens) result.append(token);
```

#### 6. 2～3 分钟面试口述

> String 的核心特征是不可变：对象创建后字符序列不能被原地修改，任何变更都会得到新对象。这样它可以安全地被多个组件共享，哈希值稳定，适合作为 HashMap Key，也能支持字符串常量池复用和安全相关场景。字面量 `"abc"` 通常引用池中的对象，而 `new String("abc")` 会显式创建新的堆对象。项目中循环拼接应使用 StringBuilder，避免大量中间对象；作为业务 Key 时也应优先选择不可变类型。

#### 7. 面试官递进追问

- String 真的是完全线程安全吗？
- 编译器怎样优化常量字符串拼接？

**记忆钩子**：String 不改自己，只创建下一份；因此能共享、能缓存、能做 Key。

### Q007：`==`、`equals` 和 `hashCode` 为什么必须一起理解？

**题型**：核心面试题　｜　**频率**：★★★★★

**为什么现在学**：这是 HashMap、HashSet、DTO 去重和领域对象比较的共同基础。

#### 1. 先用人话理解

`==` 对基本类型比较值，对对象比较是不是同一个引用。`equals` 定义业务上的内容相等。哈希集合先用 `hashCode` 缩小桶范围，再用 `equals` 确认。因此只重写 equals 不重写 hashCode，会让“逻辑相等对象”落进不同桶。

#### 2. 它在 JVM / 框架里怎么运行

1. 计算 Key 的 hashCode 并扰动
2. 根据数组长度定位桶
3. 桶内先比较 hash，再比较引用或 equals
4. 契约要求 equals 相等的对象必须具有相同 hashCode
5. 对象作为 Key 后，参与 equals/hashCode 的字段不应再变化

#### 3. 贯穿项目怎么用

用 `TenantModelKey(tenantId, modelName)` 缓存模型客户端时，必须稳定实现 equals/hashCode；适合使用不可变 record。

#### 4. 可读但容易出事故的写法

```java
class Key {
 String tenant; String model;
 public boolean equals(Object o) { return true; }
 // 未重写 hashCode
}
```

#### 5. 更稳妥的企业级写法

```java
record TenantModelKey(String tenantId, String modelName) { }
Map<TenantModelKey, Object> cache = new HashMap<>();
```

#### 6. 2～3 分钟面试口述

> `==` 和 equals 解决的问题不同：对象上的 `==` 判断是不是同一个引用，equals 判断业务内容是否相等。HashMap 与 HashSet 为了高效查找，会先用 hashCode 定位桶，再在桶内用 equals 确认。所以 equals 与 hashCode 必须遵守契约：equals 相等的对象必须拥有相同 hashCode。反过来 hashCode 相同不代表 equals 相等，因为可能哈希冲突。项目中作为 Map Key 的对象最好不可变，并一次性正确实现这两个方法，例如使用 record。

#### 7. 面试官递进追问

- 为什么 hashCode 相同不能说明对象相等？
- 可变对象作为 HashMap Key 会发生什么？

**记忆钩子**：先 hash 找小区，再 equals 找门牌。

### Q008：final、static 和不可变对象在企业代码中分别解决什么？

**题型**：场景面试题　｜　**频率**：★★★★☆

**为什么现在学**：早期八股把关键字逐个背诵，项目中更重要的是理解生命周期、共享范围和状态约束。

#### 1. 先用人话理解

`static` 属于类，整个类加载器范围通常共享一份；`final` 表示变量只能赋值一次、方法不能被重写或类不能继承，但 final 引用指向的对象仍可能可变。真正的不可变对象要求内部状态也不能被外部修改。

#### 2. 它在 JVM / 框架里怎么运行

1. 类初始化时准备和赋值静态字段
2. 实例字段跟随对象存在
3. final 字段在构造完成后具有额外的安全发布语义
4. 不可变类通常使用 final 字段、防御性复制、不暴露修改方法

#### 3. 贯穿项目怎么用

模型路由规则可建模为不可变配置快照；不要把租户请求状态放到 static Map 中，否则会跨请求共享并引发并发和泄漏问题。

#### 4. 可读但容易出事故的写法

```java
static Map<String, AgentContext> contexts = new HashMap<>();
// 永久持有请求对象，且线程不安全
```

#### 5. 更稳妥的企业级写法

```java
public record ModelPolicy(String model, Duration timeout) {}
private final ConcurrentMap<String, ModelPolicy> policies = new ConcurrentHashMap<>();
```

#### 6. 2～3 分钟面试口述

> `static` 决定成员属于类级共享状态，`final` 约束引用或定义不能再次改变，但 final 引用不代表对象内部不可变。不可变对象还要保证所有字段在构造时确定、内部可变数据做防御性复制，并且不暴露修改入口。企业代码中我会尽量用 final 依赖和不可变配置快照，让状态边界清晰；static 更适合无状态常量或明确管理的全局组件，不适合保存请求上下文。final 字段还利于安全发布，但共享可变对象仍需要并发控制。

#### 7. 面试官递进追问

- `final List` 为什么仍能 add？
- static 变量在哪个类加载器边界内共享？

**记忆钩子**：static 管共享，final 管重新赋值，不可变管整个状态。

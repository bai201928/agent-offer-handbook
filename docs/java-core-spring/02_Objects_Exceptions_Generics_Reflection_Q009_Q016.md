# 第 2 章：把对象、异常、泛型和框架魔法还原成普通 Java

## 本章目标

从面向对象走到 Spring 所依赖的反射、注解和代理基础；同时掌握项目中真正会用到的异常与泛型边界。

## 前置知识

完成第 1 章，知道对象、引用、方法调用和类加载的基本含义。

## 本章学习路径

```text
封装对象 → 接口抽象 → 多态调用 → 泛型约束 → 异常边界 → 反射/注解 → 现代数据载体
```

> 本章不是按旧八股文件的出现顺序排列，而是按“先能运行，再解释原理，最后处理故障”的认知顺序组织。

### Q009：封装、继承、多态到底解决了什么问题？

**题型**：核心面试题　｜　**频率**：★★★★★

**为什么现在学**：不是为了背三个定义，而是为了理解 Spring 为什么依赖接口、代理和可替换实现。

#### 1. 先用人话理解

封装把状态和操作放在一起并控制外部访问；继承复用父类行为，但也会形成强耦合；多态让调用方依赖抽象，运行时可以替换实现。企业代码通常更推荐“接口 + 组合”而不是深层继承。

#### 2. 它在 JVM / 框架里怎么运行

1. 接口或父类定义稳定契约
2. 不同实现类各自完成细节
3. 调用方只持有抽象类型引用
4. 运行时通过实际对象类型完成动态分派
5. 组合把变化能力作为依赖注入，而不是写死在继承树中

#### 3. 贯穿项目怎么用

Agent 平台定义 `ModelClient` 接口，OpenAI、通义和本地模型各自实现；路由器无需 if-else 了解每个 SDK。

#### 4. 可读但容易出事故的写法

```java
class AgentService extends OpenAiClient { /* 业务被具体供应商绑死 */ }
```

#### 5. 更稳妥的企业级写法

```java
interface ModelClient { String chat(String prompt); }
final class AgentService {
  private final ModelClient client;
  AgentService(ModelClient client) { this.client = client; }
}
```

#### 6. 2～3 分钟面试口述

> 封装解决的是状态边界，把对象内部实现隐藏起来；继承表达 is-a 关系并复用行为，但继承层级过深会让修改影响扩散；多态让调用方依赖抽象，在运行时使用不同实现。企业项目里我更偏向接口和组合，例如 AgentService 只依赖 ModelClient，具体模型供应商通过 Spring 注入。这样新增模型实现不需要修改核心业务，也方便测试替身和灰度切换。继承更适合稳定的类型层次，而不是为了少写几行代码。

#### 7. 面试官递进追问

- 多态的运行时绑定发生在哪里？
- 为什么组合通常比继承更容易维护？

**记忆钩子**：封装守边界，继承表达类型，多态替换实现。

### Q010：接口和抽象类怎么选？

**题型**：高频基础题　｜　**频率**：★★★★★

**为什么现在学**：它直接影响领域模型、插件 SPI、模板流程和扩展点设计。

#### 1. 先用人话理解

接口更像能力合同，一个类可以实现多个接口；抽象类除了合同，还能保存公共状态、构造规则和部分实现。选择关键不在语法，而在是否存在稳定的共同状态和模板流程。

#### 2. 它在 JVM / 框架里怎么运行

1. 接口定义行为边界并支持多实现
2. 抽象类可包含实例字段、构造器和受保护模板方法
3. 接口默认方法适合小范围兼容演进，不应堆积复杂状态
4. 调用方优先依赖接口，框架骨架可使用抽象类实现模板方法

#### 3. 贯穿项目怎么用

MCP 工具适合 `Tool` 接口；多个工具都需要统一鉴权、重试和指标骨架时，可提供 `AbstractToolExecutor` 作为可选基类。

#### 4. 可读但容易出事故的写法

```java
abstract class Tool { /* 所有插件被迫继承，无法再继承别的类 */ }
```

#### 5. 更稳妥的企业级写法

```java
interface Tool { ToolResult execute(ToolRequest request); }
abstract class AbstractToolExecutor implements Tool {
  protected final void audit(ToolRequest r) { }
}
```

#### 6. 2～3 分钟面试口述

> 接口用于定义可替换能力，抽象类用于表达共享状态和模板流程。一个类可以实现多个接口，但只能继承一个类，所以面向扩展的公共契约通常优先接口；如果多个实现确实共享构造依赖、受保护方法和固定执行骨架，可以增加抽象类，但调用方仍最好依赖接口。项目里模型客户端、工具和存储适配器都适合接口；统一的工具执行模板可以用抽象类实现鉴权、审计、调用和异常转换。

#### 7. 面试官递进追问

- 接口默认方法会不会破坏接口隔离原则？
- 什么时候抽象类比工具类更合适？

**记忆钩子**：能力用接口，骨架用抽象类，调用方依赖最小合同。

### Q011：重载、重写和运行时多态有什么区别？

**题型**：高频基础题　｜　**频率**：★★★★☆

**为什么现在学**：Spring 代理、策略实现和方法匹配都依赖方法签名，混淆重载与重写会导致错误判断。

#### 1. 先用人话理解

重载发生在同一个类中，方法名相同但参数列表不同，编译期决定调用哪个；重写发生在子类中，签名兼容，运行时根据实际对象选择实现。返回值不能单独构成重载。

#### 2. 它在 JVM / 框架里怎么运行

1. 编译器根据静态类型和参数列表解析重载
2. JVM 对虚方法调用使用实际对象类型进行动态分派
3. static、private 和 final 方法不能形成普通运行时重写
4. 重写要遵守可见性、异常和返回类型协变规则

#### 3. 贯穿项目怎么用

模型客户端可重载不同请求形式，但供应商实现应重写统一 `chat(ChatRequest)` 契约；不要期望代理拦截 private 方法。

#### 4. 可读但容易出事故的写法

```java
class Client { void chat(Object x){} }
class OpenAiClient extends Client { void chat(String x){} } // 这是重载，不是重写
```

#### 5. 更稳妥的企业级写法

```java
class OpenAiClient extends Client {
 @Override void chat(Object x) { /* 真正重写 */ }
}
```

#### 6. 2～3 分钟面试口述

> 重载是同名不同参数，属于编译期多态，编译器根据变量静态类型和参数列表选方法；重写是子类替换父类可覆盖方法，属于运行时多态，JVM 根据实际对象类型分派。常见坑是子类写了一个参数更具体的同名方法，却误以为重写，因此应使用 `@Override` 让编译器校验。Spring AOP 只能代理可拦截的方法，private、final 等方法也有边界。

#### 7. 面试官递进追问

- 为什么返回类型不同不能构成重载？
- 桥接方法和泛型擦除有什么关系？

**记忆钩子**：重载编译时选签名，重写运行时选对象。

### Q012：Java 泛型解决什么？类型擦除和 PECS 怎么理解？

**题型**：核心面试题　｜　**频率**：★★★★★

**为什么现在学**：集合、Spring 容器、序列化和插件接口大量使用泛型；只会写 `List<T>` 不足以应对追问。

#### 1. 先用人话理解

泛型把类型错误提前到编译期，并减少强制转换。Java 泛型主要通过类型擦除实现，运行时通常看不到完整类型参数，因此不能直接 `new T()` 或创建 `T[]`。通配符使用口诀是 PECS：生产数据用 `extends`，消费数据用 `super`。

#### 2. 它在 JVM / 框架里怎么运行

1. 编译器检查类型并在必要处插入转换
2. 编译后大部分类型参数被擦除为上界或 Object
3. 反射可从声明元数据读取部分泛型信息，但对象本身没有 `List<String>` 独立运行时类
4. `? extends T` 适合读取 T，不能安全写入具体子类
5. `? super T` 适合写入 T，读取时只能视为 Object

#### 3. 贯穿项目怎么用

工具注册中心读取 `List<? extends Tool>`；批量填充消费者可接收 `Collection<? super ToolResult>`。

#### 4. 可读但容易出事故的写法

```java
void copy(List<Object> target, List<String> source) { } // List<Object> 不是 List<String> 的父类型
```

#### 5. 更稳妥的企业级写法

```java
static <T> void copy(List<? super T> out, List<? extends T> in) {
  out.addAll(in);
}
```

#### 6. 2～3 分钟面试口述

> 泛型的价值是让类型约束发生在编译期，减少运行时转换错误。Java 采用类型擦除实现，所以 `List<String>` 和 `List<Integer>` 运行时通常是同一个 List 类，不能直接 new T，也不能用 instanceof 判断具体类型参数。通配符要结合数据方向理解：只从容器读取 T 使用 `? extends T`，向容器写入 T 使用 `? super T`，即 PECS。工程上泛型应表达清晰合同，避免层层通配符让 API 难以使用。

#### 7. 面试官递进追问

- 为什么泛型数组受限制？
- 什么是桥接方法？

**记忆钩子**：泛型管编译期；生产 extends，消费 super。

### Q013：Java 异常体系怎么分？项目中该怎样设计异常边界？

**题型**：核心面试题　｜　**频率**：★★★★★

**为什么现在学**：Agent 调用外部模型、数据库和工具时失败很多，异常设计决定重试、回滚和用户提示是否正确。

#### 1. 先用人话理解

`Throwable` 下有 Error 和 Exception。Error 通常表示 JVM 或环境严重问题，不应被业务随意吞掉；Exception 中 checked 异常要求显式处理，RuntimeException 表示运行期错误。项目里更重要的是把底层异常转换为有业务语义、可观测、可判断是否重试的异常。

#### 2. 它在 JVM / 框架里怎么运行

1. 底层 SDK 抛出网络、超时或协议异常
2. 适配器层记录关键上下文并转换为领域异常
3. 服务层决定重试、降级、事务回滚或向上抛出
4. 入口层统一映射错误码与安全的用户消息
5. 日志保留 cause，不能只打印 message

#### 3. 贯穿项目怎么用

将模型 429 转为 `ModelRateLimitException`，超时转为 `ModelTimeoutException`；重试器只重试明确的瞬时失败。

#### 4. 可读但容易出事故的写法

```java
try { model.call(req); }
catch (Exception e) { return ""; } // 吞异常，无法区分失败
```

#### 5. 更稳妥的企业级写法

```java
try { return model.call(req); }
catch (SdkTimeoutException e) {
  throw new ModelTimeoutException(req.traceId(), e);
}
```

#### 6. 2～3 分钟面试口述

> Java 异常分为 Error 和 Exception。Error 多数代表 JVM 或资源级严重问题，业务通常不应捕获后继续假装成功；Exception 又分受检异常和运行时异常。企业项目中我不会只背分类，而会设计异常边界：基础设施异常在适配器层转换为领域异常，保留原始 cause、错误码和 Trace ID；服务层依据异常类型决定重试、降级或回滚；Controller 统一输出安全错误响应。最危险的是 catch Exception 后吞掉或返回默认值，它会把失败伪装成成功。

#### 7. 面试官递进追问

- Spring 事务默认对哪些异常回滚？
- 为什么不建议把所有异常都包装成同一个 BusinessException？

**记忆钩子**：异常要分类、转换、保留原因，再决定重试或回滚。

### Q014：try-with-resources 为什么比 finally 手动关闭更可靠？

**题型**：场景面试题　｜　**频率**：★★★☆☆

**为什么现在学**：数据库游标、文件流、HTTP 响应和 JDBC 资源都需要确定释放。

#### 1. 先用人话理解

实现 `AutoCloseable` 的资源可以放在 try 括号中，编译器生成可靠的关闭逻辑。即使业务抛异常，资源也会按创建的逆序关闭；关闭时再次抛出的异常会作为 suppressed exception 保留，不会覆盖主异常。

#### 2. 它在 JVM / 框架里怎么运行

1. 资源按声明顺序创建
2. try 主体执行
3. 发生异常时记录主异常
4. 资源按逆序调用 close
5. close 异常通过 `addSuppressed` 挂到主异常上

#### 3. 贯穿项目怎么用

导入知识库文件、读取响应流和原生 JDBC 操作必须使用资源边界；连接池归还依赖 close，忘关会耗尽池。

#### 4. 可读但容易出事故的写法

```java
InputStream in = file.getInputStream();
parse(in); // 异常时没有 close
```

#### 5. 更稳妥的企业级写法

```java
try (InputStream in = file.getInputStream()) {
  parse(in);
}
```

#### 6. 2～3 分钟面试口述

> try-with-resources 面向实现 AutoCloseable 的资源，编译器会生成 finally 式关闭逻辑，但比手写更可靠。资源按创建的逆序关闭，主逻辑异常不会被 close 异常覆盖，后者会作为 suppressed exception 保留。企业项目中的文件流、JDBC Connection、Statement、ResultSet 和某些 HTTP 响应都应使用这种方式。需要注意 close 对连接池通常表示归还连接，而不是物理断开；因此忘记关闭最终会表现为连接池耗尽和请求超时。

#### 7. 面试官递进追问

- 如何查看 suppressed exception？
- 多个资源为什么逆序关闭？

**记忆钩子**：资源进 try 括号，异常也能按逆序归还。

### Q015：反射和注解为什么能让 Spring 看起来像“魔法”？

**题型**：核心面试题　｜　**频率**：★★★★★

**为什么现在学**：理解这一题后，IOC 扫描、依赖注入、AOP、MyBatis Mapper 和序列化都能串起来。

#### 1. 先用人话理解

注解只是附着在类、方法或字段上的元数据，本身不会自动执行。框架在编译期、类加载期或运行期读取这些元数据，再通过反射检查类型、创建对象、调用方法或生成代理。

#### 2. 它在 JVM / 框架里怎么运行

1. 类扫描找到候选 Class
2. 读取 `@Component`、`@Bean`、`@Transactional` 等元数据
3. 构建内部描述，如 BeanDefinition 或映射规则
4. 通过构造器反射实例化并注入依赖
5. 必要时生成代理，方法调用经过拦截器链

#### 3. 贯穿项目怎么用

项目自定义 `@AuditedTool` 后，BeanPostProcessor 读取注解并包装工具 Bean，统一记录耗时和结果摘要。

#### 4. 可读但容易出事故的写法

```java
@MyMarker
class Tool { } // 只写注解，不存在任何处理器，什么也不会发生
```

#### 5. 更稳妥的企业级写法

```java
// 框架代码读取注解并执行逻辑
if (type.isAnnotationPresent(MyMarker.class)) {
  registry.register(type);
}
```

#### 6. 2～3 分钟面试口述

> 注解是元数据，不具备主动执行能力；反射提供运行时观察和调用类结构的能力。Spring 扫描类后读取注解，转成 BeanDefinition，再通过反射调用构造器、注入属性，并由后处理器决定是否创建代理。MyBatis 也会为 Mapper 接口生成代理。反射的代价包括类型安全较弱、调用路径更隐蔽以及一定性能开销，所以业务代码不应滥用，但框架基础设施非常适合使用。

#### 7. 面试官递进追问

- 注解的 Retention 三种策略有什么区别？
- 反射为什么可能破坏封装？

**记忆钩子**：注解写说明，框架读说明，反射和代理把说明变成行为。

### Q016：record、sealed class 和模式匹配值得在项目里怎么用？

**题型**：现代 Java 场景题　｜　**频率**：★★★☆☆

**为什么现在学**：它们不是低频语法秀，而是可以减少 DTO 样板和封闭状态分支错误；但要知道与框架、序列化和实体对象的边界。

#### 1. 先用人话理解

`record` 适合不可变数据载体，自动生成访问器、equals/hashCode 和 toString；sealed class 限制允许的子类型；模式匹配让状态分支更完整。它们适合命令、事件和结果，不一定适合需要无参构造、懒加载和可变生命周期的 ORM 实体。

#### 2. 它在 JVM / 框架里怎么运行

1. record 构造时一次性确定组件
2. sealed 类型在编译期知道允许的实现集合
3. switch 模式可对封闭层级做穷尽检查
4. 框架兼容性取决于所用版本和序列化组件

#### 3. 贯穿项目怎么用

Agent 执行结果可定义为 `Success`、`RetryableFailure`、`PermanentFailure` 三个 sealed 子类型，避免用字符串状态和 null 组合。

#### 4. 可读但容易出事故的写法

```java
class ToolResult { String status; Object data; String error; } // 可产生非法组合
```

#### 5. 更稳妥的企业级写法

```java
sealed interface ToolResult permits Success, RetryableFailure, PermanentFailure {}
record Success(String output) implements ToolResult {}
```

#### 6. 2～3 分钟面试口述

> record 适合表达不可变的数据载体，例如请求、事件和查询结果，它自动生成组件访问器以及 equals、hashCode 和 toString。sealed class 或 interface 可以限制合法子类型，再配合模式匹配 switch，让编译器检查分支是否完整。项目里我会用它们表示 Agent 执行结果和领域事件，但不会机械替换所有类：JPA 实体、需要代理或渐进修改状态的对象仍要考虑框架约束和生命周期。

#### 7. 面试官递进追问

- record 是否天然深度不可变？
- 为什么 sealed 层级适合状态机结果？

**记忆钩子**：record 固定数据，sealed 固定类型集合，模式匹配固定分支。

# Redis 8.8 面试题 Q24

## Q24. maxmemory、Lazy Free 与容量规划应该怎样做

**类型：企业容量题｜难度：中等偏上｜重要性：★★★★★**

### ① maxmemory 不是机器总内存

容器限制 16GB，不代表可以设置：

```text
maxmemory = 16GB
```

Redis 还需要：

- 客户端缓冲；
- 复制 backlog 和连接缓冲；
- AOF 缓冲；
- 模块内存；
- allocator 与碎片；
- fork/COW；
- 操作系统空间；
- 容器运行余量。

### ② 容量公式先建立心智模型

```text
容器/机器可用内存
  - 系统与运行时
  - 峰值 COW
  - 客户端/复制/AOF 缓冲
  - 碎片与模块
  - 安全余量
= 可给数据集与 maxmemory 的空间
```

不是固定 70% 或 80%，而是用压测得出峰值。

### ③ 什么是 Lazy Free

删除巨大对象时，如果主线程同步释放所有内存，可能耗时很长。

Lazy Free：

```text
主线程快速从 Keyspace 移除引用
  ↓
后台线程逐步释放对象内存
```

`UNLINK` 是常见显式方式。

优点：减少主路径阻塞。

边界：

- 释放成本没有消失；
- 后台队列可能积压；
- CPU 仍要做工作；
- RSS 可能不会立即下降；
- 一次删除过多仍可能造成压力。

### ④ 大 Key 删除怎样做

```text
先停止继续增长
  ↓
确认是否可分批清理
  ↓
使用 UNLINK/Lazy Free
  ↓
观察 lazyfree_pending_objects、CPU、RSS
  ↓
避免批量同时触发
```

### ⑤ 容量规划需要哪些输入

- 每类 Key 数量；
- 平均与 P99 Value 大小；
- TTL；
- 增长率；
- 峰值 QPS；
- 回复字节；
- 副本数；
- 持久化方式；
- fork 写入率；
- 热点与 Slot 分布；
- 故障切换和迁槽空间。

### ⑥ 容量不是一次计算

需要持续：

```text
预测
→ 压测
→ 上线监控
→ 趋势回归
→ 扩容演练
```

### ❌ 容易制造事故的写法

```java
# 机械套用“80% 经验值”，忽略容器、COW 和缓冲。
maxmemory 13gb  # 容器上限 16GB
```

### 🎙️ 2～3 分钟优秀回答

maxmemory 不能直接等于机器或容器内存上限，因为 Redis 还需要为客户端、复制和 AOF 缓冲、模块、allocator 碎片、fork/COW 和系统运行预留空间。固定 70% 或 80% 只能作为初步估算，最终要在真实数据集和峰值写流量下压测。

Lazy Free 通过 UNLINK 等方式先从 Keyspace 移除对象，再让后台线程释放内存，能减少主路径阻塞，但成本没有消失。后台释放可能积压，RSS 也不会立即下降，因此要监控 pending 对象、CPU 和内存趋势。

容量规划会统计每类 Key 数量、P99 字节、TTL、增长率、QPS、回复、复制、持久化和 COW 峰值，并预留迁槽与故障空间。它是持续预测、压测、监控和演练的过程。

### 面试官可能继续追问

- UNLINK 返回后内存为什么没有立刻归还？
- 扩容 Cluster 时为什么还要预留迁槽空间？

> **记忆句**：maxmemory 只管数据上限，不代表进程总上限；Lazy Free 只搬工作，不消灭工作。

# 系统设计零基础课：先学会设计，再开始背题

> **目标岗位**：Java 后端、Agent 应用开发、RAG/AI 平台、微服务与基础架构岗位。  
> **贯穿项目**：NexusAgent——多租户 Agent + RAG + MCP 工具执行平台。  
> **题量**：40 道主线题，其中 28 道为 70% 必会题。

## 一、为什么原来的 79 道题不直接照搬

原材料对事实源、Outbox/Inbox、RPO/RTO、容量和复合事故讲得很深，但初学者还没学会“怎样回答一道系统设计题”，就进入 ACK、Fencing、PITR、Open-loop、协调遗漏和跨区域回切，容易记住名词却不会独立设计。

新版先安排不依赖项目背景的常问题：

```text
系统设计答题框架
→ 容量估算与负载均衡
→ 秒杀 / RPC / 短链 / 点赞 / 分布式 ID
→ 延迟取消 / 十倍流量 / Redis 扩展 / 可重入锁
→ 微服务定义与单体拆分
```

随后再进入：

```text
事实源与 ACK
→ Outbox / Inbox
→ 幂等、乱序、重试与版本
→ 缓存一致性与分布式事务
→ 容量、压测、背压和事故
→ Agent/RAG 项目深挖
```

## 二、系统设计面试的六步法

```text
1. 澄清需求和成功条件
2. 给出规模假设和容量模型
3. 定义业务对象、状态机和事实源
4. 画最小正常链
5. 按失败窗口逐层演进
6. 用指标、压测、对账和容灾证明
```

### 第一步：澄清需求

至少询问：

- 谁使用；
- 核心读写流程；
- 峰值和突发；
- 是否允许异步；
- 哪些数据不能丢；
- 哪些操作不可逆；
- 延迟、成本和合规边界。

### 第二步：声明假设

面试官不给数字时，可以说：

```text
“我先假设峰值 10,000 QPS，读写比 9:1，
单对象 2KB，保存 3 年。后续设计会说明，
如果规模或一致性要求改变，哪些组件需要演进。”
```

未知数字必须叫“假设”，不能伪装行业事实。

### 第三步：先定义状态

任何系统先回答：

```text
对象是谁？
状态保存在哪里？
谁能修改？
怎样算成功？
失败后谁恢复？
```

### 第四步：画最小链

```text
Client
  → Gateway
  → Business Service
  → MySQL 事实
  → Redis / MQ / Search 派生能力
```

先用最简单方案跑通，再说明什么条件让它失效。

### 第五步：处理失败窗口

每加一个组件都问：

```text
它解决了什么？
它可能重复、丢失、陈旧还是积压？
谁拥有最终事实？
失败后怎样收敛？
```

### 第六步：证明设计

高分回答一定包含：

- P95/P99 与业务成功率；
- 唯一约束、版本和幂等冲突；
- MQ Lag 与最老消息年龄；
- 缓存/索引版本差；
- 故障注入；
- 数据对账；
- RPO/RTO 与回切演练。

## 三、通用数据与可靠性词典

| 术语 | 初学者解释 |
|---|---|
| 事实源 | 对某项业务状态拥有最终裁决权的位置 |
| 派生状态 | 可从事实重建的缓存、搜索或统计 |
| 幂等 | 重复执行只产生一个等价业务效果 |
| Fencing | 新持有者用更高令牌让资源端拒绝旧写 |
| Outbox | 业务事务内同时保存待发布事件 |
| Inbox | 消费者记录事件已处理，拦截重复 |
| Deadline | 整条链剩余的绝对完成时间 |
| Backpressure | 下游处理不过来时要求上游减速 |
| RPO | 灾难后最多能丢多少数据 |
| RTO | 灾难后多久恢复约定业务能力 |

## 四、答题深度分层

```text
普通面试：
需求 → 主链 → 数据库/缓存/MQ → 一个失败窗口

高薪面试：
再补状态机、事实源、幂等、版本、容量和监控

资深深挖：
再补故障矩阵、灾备、回切、对账和验证证据
```

## 五、贯穿项目 NexusAgent

```text
用户提交 Run
  → MySQL 保存 Run + Manifest + Outbox
  → RocketMQ 触发 Worker
  → Worker 检索 Milvus、调用模型
  → MCP Gateway 审批并执行工具
  → Redis 保存热点和协调状态
  → RunEvent 驱动 SSE
  → Reconciler 扫描 UNKNOWN 和中间态
```

关键边界：

```text
MySQL：Run、权限、版本、审批、ToolOperation、Outbox 事实
Redis：热点、限流、租约、可重建 Checkpoint
RocketMQ：至少一次触发与事件传播
Milvus：带知识/权限版本的派生索引
模型：生成候选，不拥有业务写权
MCP Gateway：权限、Schema、审批、幂等和审计边界
```

## 三轮学习法

### 第一轮：只讲人话和主链

每题先遮住答案，用 60 秒回答：

```text
目标是什么？
核心对象是什么？
数据放在哪里？
正常链怎么走？
```

### 第二轮：完成 2～3 分钟回答

```text
结论与边界
→ 正常数据流
→ 一个并发或失败窗口
→ 企业级改进
→ 指标与取舍
```

### 第三轮：接受资深追问

```text
组件超时但可能成功怎么办？
消息重复和乱序怎么办？
旧 Worker 或旧主复活怎么办？
十倍流量时先保护谁？
怎样证明恢复后数据正确？
```

## 15 个必须纠正的错误

1. 系统设计不是先画 Redis、MQ 和微服务。
2. 平均 QPS 不能代表峰值、突发和长尾。
3. 有缓存不代表数据库不会被击穿。
4. 有 MQ 不代表消息只处理一次。
5. 有副本不代表零丢失，也不等于备份。
6. HTTP 200 不代表所有下游业务完成。
7. Redis Cluster 不能自动拆分单个热 Key。
8. 分布式锁不能阻止过期旧持有者继续写。
9. Snowflake ID 不能替代业务幂等键。
10. 延迟消息不能替代订单状态机。
11. 微服务不是把技术层拆成多个进程。
12. `@Transactional` 不能覆盖多个远程系统。
13. 扩 Pod、连接池和超时可能放大下游故障。
14. Prompt Injection 不能只靠提示词解决。
15. 服务变绿不等于业务事实、索引和副作用已经恢复。
